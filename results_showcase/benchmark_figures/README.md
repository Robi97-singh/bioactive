# Benchmark Comparison Figures

Publication figures for the backbone bioactivity benchmark, styled after the two most important
plots of Fredin Haslum et al. (*Nature Communications* 15:3470, 2024): the per-assay ROC-AUC
boxplot (their Fig 1c) and the model comparison with Friedman + Nemenyi statistical testing
(their Fig 2a). All results are on JUMP-CP source_11, 29 assays, 6-fold CV. Generated by
`make_benchmark_figures.py`, `make_adaptation_figure.py`, and `make_pr_calibration_pareto.py`.

## Findings

1. **Domain-matched pretraining wins.** Cell-DINO (pretrained on Cell Painting) significantly beats generic ImageNet DINOv2-Base (Nemenyi p=0.0044) and DINOv2-Large (p=0.0139) -- with a smaller model in both cases.
2. **Scale alone does not help, frozen.** DINOv2-Large (304M params) is statistically indistinguishable from DINOv2-Base (86M params) -- p=0.9974 -- despite a 3.5x increase in parameters, holding architecture and pretraining domain fixed. This isolates parameter count as not the active ingredient behind CLIP-L's earlier scale advantage; pretraining data volume/diversity is the more likely driver. A third size point, frozen DINOv2-Small (22M params, 0.5786 ± 0.0051), lands within 0.001 ROC-AUC of both Base and Large -- consistent with the same conclusion across a 14x parameter range, though this third point is not yet part of the formal Nemenyi test above.
3. **"Biomedical" is not domain-matched.** BiomedCLIP is statistically indistinguishable from generic ImageNet DINOv2-Base (p=0.9938) and DINOv2-Large (p=1.0000) -- nominal biomedical relevance does not help. It is, however, now significantly worse than Cell-DINO (p=0.0181), reinforcing that domain-matched pretraining specifically (not just "biomedical" branding) is what matters.
4. **Resolution is model-dependent.** It helps fine-tuned ResNet (+1.5 pts) and frozen DINOv2 (+0.9 pts, pretrained at 224) but not frozen Cell-DINO (pretrained at 128px). A frozen backbone benefits from higher resolution only when it stays close to its pretraining resolution.
5. **Cheap adaptation recovers most of the gap, isolated from backbone size.** LoRA (2.4% of parameters trainable) is now a completed 6-fold result (0.6373 ± 0.0203), and with the addition of a frozen DINOv2-Small baseline -- the same backbone LoRA is built on, run through the identical locked recipe as every other frozen arm -- the gap-recovery estimate can finally be computed without a backbone-size confound: (0.6373 - 0.5786) / (0.6638 - 0.5786) = **68.9%** of the frozen-to-fine-tuned gap, at 2.4% of the training cost. This is a genuine backbone-size-controlled number, not an artifact of comparing LoRA's smaller base model against DINOv2-Base's frozen result.
6. **Fine-tuning remains the strongest option, though the margin over domain-matched frozen features is narrower than it first appeared.** ResNet significantly beats DINOv2-Base, DINOv2-Large, and BiomedCLIP (all p<0.001), and sits above LoRA -- but the gap to Cell-DINO specifically is no longer statistically significant at the 5-arm correction (p=0.0605, borderline).

## Design decisions

**1. Figure B is 224-only and frozen + ResNet, by design.** The rigorous statistical comparison
uses a single matched resolution (224) so the Friedman/Nemenyi test isolates the backbone
question from resolution. Mixing 224/448 variants would confound the two.

**2. LoRA and its same-backbone frozen baseline are shown in Figure D, not Figure B.** LoRA's
6-fold run is now complete (0.6373 ± 0.0203, all folds landed), and Figure D now also plots frozen
DINOv2-Small directly beside it -- the same backbone LoRA adapts, run frozen through the locked
recipe -- so the adaptation-spectrum bar chart makes the size-controlled comparison visually
explicit rather than requiring a caption caveat. Neither arm is mixed into the Figure B/E
significance test: LoRA is a different training regime (adapter fine-tuning, own recipe) and
frozen DINOv2-Small has not yet been folded into `make_benchmark_figures.py`'s arm list, so it
does not affect the existing 5-arm Nemenyi correction factor. Figs F (PR curves), G (calibration),
and H (Pareto efficiency) do include all 8 arms with saved per-sample predictions, since those are
regime/efficiency comparisons rather than a corrected significance test.

**3. 448 exists only for the DINO-family backbones.** BiomedCLIP and CLIP hard-downsample input
to 224 internally and use fixed 224px positional embeddings, so a genuine 448 arm is not
possible without positional-embedding surgery and off-distribution extrapolation of a CLIP
image-text projection. They are evaluated at 224 only and excluded from Figure C. DINOv2-Large's
448 arm is complete (0.5888 ± 0.0071) and included in Figure C.

**4. The resolution effect is a finding, not an omission** -- see finding 4.

**5. Individual-assay ROC curves (the reference paper's Fig 1d) are not included for most arms.**
The pipeline saved per-assay AUC scalars, not per-sample predictions, so drawing ROC curves
would need a re-inference pass. (The LoRA, ResNet, and frozen-probe test evaluations do save
`test_labels.csv` / `test_preds.csv` per fold for the arms plotted in Figs F/G/H, so ROC curves
are available for those if wanted.) The per-assay boxplots already convey per-assay discrimination.

**6. Frozen DINOv2-Small was added to close a backbone-size confound, not as a new headline arm.**
An earlier version of this benchmark compared LoRA (built on DINOv2-Small) against the frozen
DINOv2-**Base** result as if adaptation method were the only variable changing -- but the two
backbones differ 4x in parameter count. Adding a frozen DINOv2-Small arm, run through the exact
same locked recipe as every other frozen backbone, gives a true apples-to-apples baseline for the
LoRA comparison (finding 5) and a third data point for the scale-invariance finding (finding 2).

## Reproducing

```bash
# in a pod with pandas / matplotlib / scipy / scikit-posthocs / scikit-learn:
python make_benchmark_figures.py      # figs A, B, C, E + Nemenyi + summary
python make_adaptation_figure.py      # fig D (adaptation spectrum, incl. frozen DINOv2-Small)
python make_pr_calibration_pareto.py  # figs F, G, H (PR / calibration / Pareto, all 8 arms)
# read /shared/ssd/logs/b-r-singh1/results/cv/{arm}/cv_per_assay.csv
# write figures to results/figures/
```
