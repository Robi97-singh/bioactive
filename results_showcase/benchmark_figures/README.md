# Benchmark Comparison Figures

Publication figures for the backbone bioactivity benchmark, styled after the two most important
plots of Fredin Haslum et al. (*Nature Communications* 15:3470, 2024): the per-assay ROC-AUC
boxplot (their Fig 1c) and the model comparison with Friedman + Nemenyi statistical testing
(their Fig 2a). All results are on JUMP-CP source_11, 29 assays, 6-fold CV, corrected for
compound-level aggregation. Generated by `make_benchmark_figures.py`, `make_adaptation_figure.py`,
and `make_pr_calibration_pareto.py`.

## Findings

1. **Domain-matched pretraining no longer shows a statistically significant edge.** Cell-DINO's
   mean (0.6373) is numerically highest, and critically, it is statistically indistinguishable
   from fine-tuned ResNet50 (p=0.7693) -- frozen, domain-matched features now match full
   fine-tuning on this benchmark. But Cell-DINO is also not significantly different from any
   generically-pretrained frozen backbone (DINOv2-Base p=0.7693, DINOv2-Large p=0.7693,
   DINOv3-Base p=0.3018, BiomedCLIP p=0.1217, CLIP-L p=0.1047). The "domain pretraining clearly
   wins" headline from the pre-correction analysis does not survive compound-level aggregation.
2. **Scale alone does not help, frozen.** DINOv2-Large (304M params) remains statistically
   indistinguishable from DINOv2-Base (86M params) -- p=1.0000 -- despite a 3.5x increase in
   parameters, holding architecture and pretraining domain fixed. Frozen DINOv2-Small (22M
   params, 0.6283 +/- 0.0144) also lands close to both, extending the conclusion across a 14x
   parameter range (not yet part of the formal Nemenyi test above).
3. **"Biomedical" is not domain-matched, and is no longer distinguishable from Cell-DINO either.**
   BiomedCLIP remains statistically indistinguishable from generic ImageNet DINOv2-Base
   (p=0.9108) and DINOv2-Large (p=0.9108) -- nominal biomedical relevance still does not help.
   Unlike the pre-correction result, it is now also *not* significantly different from Cell-DINO
   (p=0.1217, was p=0.0181 "significant" before correction) -- the "domain-matched beats
   biomedical" distinction no longer holds up statistically.
4. **Resolution hurts every DINO-family frozen backbone except DINOv3-Base.** Cell-DINO
   (0.6373 -> 0.6203, -1.70 pts), DINOv2-Base (0.6345 -> 0.6211, -1.34 pts), and DINOv2-Large
   (0.6313 -> 0.6216, -0.97 pts) all get *worse* at 448 when frozen. DINOv3-Base is the sole
   exception, improving (0.6332 -> 0.6448, +1.16 pts). Fine-tuned ResNet50 also improves with
   resolution (0.6638 -> 0.6792, +1.54 pts). This is a full reversal of the pre-correction
   finding, which reported DINOv2 improving (+0.9 pts) and only Cell-DINO being flat.
5. **Cheap adaptation recovers about a quarter of the gap, not two-thirds.** LoRA (2.4% of
   parameters trainable, 0.6373 +/- 0.0203) compared against its correct same-backbone frozen
   baseline (DINOv2-Small, 0.6283 +/- 0.0144, not the larger DINOv2-Base used in an earlier
   version of this estimate): (0.6373 - 0.6283) / (0.6638 - 0.6283) = **25.4%** of the
   frozen-to-fine-tuned gap recovered, at 2.4% of the training cost. The pre-correction estimate
   of 68.9% combined two separate errors -- the evaluation bug, and comparing LoRA against a
   4x-larger frozen backbone than the one it's built on.
6. **Fine-tuning is the strongest arm on average, but the margin over domain-matched frozen
   features has disappeared statistically.** ResNet50 significantly beats DINOv3-Base, BiomedCLIP,
   and CLIP-L (locked recipe) (all p<0.01), but is *not* significantly different from Cell-DINO
   (p=0.7693) and only borderline non-significant against DINOv2-Base and DINOv2-Large
   (p=0.0546). This is the single largest change from the pre-correction analysis, which reported
   ResNet significantly ahead of every frozen arm (all p<0.001).

## Design decisions

**1. Figure B is 224-only and frozen + ResNet, by design.** The rigorous statistical comparison
uses a single matched resolution (224) so the Friedman/Nemenyi test isolates the backbone
question from resolution. Mixing 224/448 variants would confound the two.

**2. LoRA and its same-backbone frozen baseline are shown in Figure D, not Figure B.** LoRA's
6-fold run (0.6373 +/- 0.0203) and the frozen DINOv2-Small baseline (0.6283 +/- 0.0144, the same
backbone LoRA adapts, run through the locked recipe) are plotted together in Figure D so the
size-controlled comparison is visually explicit rather than requiring a caption caveat. Neither
arm is in the Figure B/E significance test: LoRA is a different training regime (adapter
fine-tuning, own recipe), and frozen DINOv2-Small is not yet folded into the formal Nemenyi
correction. Figs F (PR curves), G (calibration), and H (Pareto efficiency) include all arms with
saved per-sample predictions, since those are regime/efficiency comparisons rather than a
corrected significance test.

**3. 448 exists only for the DINO-family backbones.** BiomedCLIP and CLIP hard-downsample input
to 224 internally and use fixed 224px positional embeddings, so a genuine 448 arm is not
possible without positional-embedding surgery and off-distribution extrapolation of a CLIP
image-text projection. They are evaluated at 224 only and excluded from Figure C. All four
DINO-family 448 arms are complete and included in Figure C: Cell-DINO (0.6203 +/- 0.0115),
DINOv2-Base (0.6211 +/- 0.0084), DINOv2-Large (0.6216 +/- 0.0195), and DINOv3-Base
(0.6448 +/- 0.0180) -- see finding 4 above for the resolution-effect result itself.

**4. The resolution effect is a finding, not an omission** -- see finding 4.

**5. Individual-assay ROC curves (the reference paper's Fig 1d) are not included for most arms.**
The pipeline saved per-assay AUC scalars, not per-sample predictions, so drawing ROC curves
would need a re-inference pass. (The LoRA, ResNet, and frozen-probe test evaluations do save
`test_labels.csv` / `test_preds.csv` per fold for the arms plotted in Figs F/G/H, so ROC curves
are available for those if wanted.) The per-assay boxplots already convey per-assay discrimination.

**6. Frozen DINOv2-Small was added to close a backbone-size confound, not as a new headline arm.**
An earlier version of this benchmark compared LoRA (built on DINOv2-**Small**) against the frozen
DINOv2-**Base** result as if adaptation method were the only variable changing -- but the two
backbones differ 4x in parameter count. Adding a frozen DINOv2-Small arm, run through the exact
same locked recipe as every other frozen backbone, gives a true apples-to-apples baseline for the
LoRA comparison (finding 5) and a third data point for the scale-invariance finding (finding 2).

## Reproducing

```bash
# in a pod with pandas / matplotlib / scipy / scikit-posthocs / scikit-learn:
python make_benchmark_figures.py      # figs A, B, C, E + Nemenyi + summary
python make_adaptation_figure.py      # fig D (adaptation spectrum, incl. frozen DINOv2-Small)
python make_pr_calibration_pareto.py  # figs F, G, H (PR / calibration / Pareto, all arms)
# read /shared/ssd/logs/b-r-singh1/results/cv/{arm}/cv_per_assay.csv
# write figures to results/figures/
```
